## التحديثات التالية

1. ابدأ من هذه النسخة، وراجع `git status` و`git diff` قبل حفظ التغييرات.
2. اختبر التحديث محليًا باستخدام `npm run typecheck` و`npm run build` ومعاينة الواجهة.
3. أضف الملفات المقصودة فقط ثم أنشئ commit وصفيًا، وارفعه بـ `git push origin main`.
4. عند اعتماد تحديث التشغيل المحلي، استخدم `npm run local:release` لحفظ لقطة
   جديدة وصورة Docker قبل تفعيلها. لا تستبدل علامة النسخة المعتمدة القديمة.
5. إذا وُجدت تحديثات بعيدة، افحصها أولًا؛ لا تستخدم force push أو reset لحل اختلاف التاريخ.

الرفع إلى GitHub لا يحدث تلقائيًا عند حفظ الملفات، ولا يُحدّث Docker أو الموقع
المنشور تلقائيًا. لا يوجد إعداد نشر تلقائي ضمن هذا الربط.

## حدود النسخ الاحتياطي

GitHub يحفظ المصدر والأصول وإعدادات البناء وتاريخ Git، وليس صور Docker نفسها.
تبقى `.local-releases/` وملفات `image.tar` محلية ومستبعدة من Git. كذلك لا تُرفع
ملفات البيئة والأسرار أو `node_modules/` أو مخرجات البناء. احتفظ بنسخة مستقلة
من أرشيف الصورة إذا كنت تحتاج استرجاع نفس الصورة حرفيًا؛ إعادة البناء من
المصدر قد تستخدم صور أساس أحدث لأن أسماء صور الأساس في Dockerfile متحركة.
