# تشغيل ORBITS LINKS محلياً وحفظ الإصدارات

لا يغيّر هذا الإعداد تصميم الموقع ولا ينشر إلى Sites. يشغّل نسخة إنتاج ثابتة من المشروع داخل Docker Desktop على هذا الجهاز فقط.

- الصفحة الرئيسية الحالية: http://localhost:4173/
- نموذج Visibility المستقل: http://localhost:4173/visibility/
- ربط المنفذ على `127.0.0.1` فقط؛ ليس خادماً متاحاً للإنترنت أو الشبكة المحلية.

## التشغيل والتحديث

من مجلد المشروع، مع تشغيل Docker Desktop:

```sh
npm run local:release
```

استخدم هذا الأمر بعد كل تحديث تريد حفظه وتشغيله. يأخذ لقطة من ملفات المشروع، ويبني إصداراً جديداً، ويحفظ صورة Docker في `image.tar` قبل تفعيل الإصدار. لا يتوقف الإصدار السابق أثناء البناء. إذا فشل تفعيل إصدار جديد يحاول إعادة الإصدار المحدد سابقاً.

لا يراقب كل ضغطة حفظ تلقائياً، ولا ينشئ Git commits نيابة عنك. التعديلات التي لم تستخدم معها الأمر أعلاه لا تصبح إصدارات تشغيل محفوظة. احتفظ أيضاً بتاريخ المصدر في Git.

## إدارة النسخة

```sh
npm run local:status
npm run local:releases
npm run local:stop
npm run local:start
npm run local:rollback -- RELEASE_ID
```

استبدل `RELEASE_ID` بالمعرّف الكامل من قائمة الإصدارات. الرجوع يبدّل نسخة التشغيل فقط ولا يكتب فوق كود المشروع. لا تستخدم `docker compose up` مباشرةً؛ الأوامر أعلاه تختار الصورة الصحيحة وتتحقق منها.

## ما الذي يُحفظ؟

كل إصدار له مجلد مستقل داخل `.local-releases/` يحتوي على:

- `source/`: لقطة من المصدر والأصول وإعدادات التشغيل، بما فيها التعديلات غير الملتزم بها.
- `image.tar`: نسخة قابلة لإعادة التحميل من صورة التشغيل، حتى لو حُذفت الصورة من Docker.
- `release.json`: معرّف الصورة، تاريخ البناء ومرجع Git الأساسي.

ملفات البيئة والأسرار وبيانات `.git` والاعتماديات المحلية ليست ضمن اللقطة. الصورة مبنية من مصدر اللقطة لا من ملفات متغيرة مربوطة بالحاوية. كل الإصدارات محفوظة دون حذف تلقائي؛ راقب مساحة القرص.

هذه نسخ محلية على نفس الجهاز وليست حماية من فقد الجهاز. انسخ `.local-releases` ومستودع المصدر إلى قرص خارجي أو وجهة نسخ احتياطي معتمدة لاحقاً. صورة التشغيل خاصة بمعمارية الجهاز الذي بُنيت عليه؛ الانتقال لمعمارية أخرى يتطلب إعادة بناء المصدر.

بيانات workspace الحالية المخزنة في المتصفح لا تُنسخ مع Docker، وستكون بيانات `localhost:4173` مستقلة عن `localhost:3000` وعن النسخة المنشورة. نموذج Visibility نفسه لا يحفظ الإجابات بعد إعادة تحميل الصفحة.

الحاوية تعود تلقائياً مع Docker Desktop ما لم توقفها يدوياً. تشغيل Docker Desktop بعد إعادة تشغيل الجهاز يبقى بحسب إعداداته الحالية؛ لم يتم تغيير إعدادات بدء تشغيل الجهاز.
